# Проект инструментов создания объявлений

Статус: интерфейс реализован; реальные операции создания и загрузки не выполнялись.
Дата сверки API: 7 ноября 2026 года.
Источник: [официальная документация Telegram Ads API](https://ads.telegram.org/docs/api),
прочитанная в авторизованной браузерной сессии, и интерфейс TeleAd 0.1.1.

## Набор инструментов

Два инструмента для первой реализации:

| MCP-инструмент | Задача | Методы Telegram Ads API |
|---|---|---|
| `create_ads` | Создать одно или несколько объявлений в одном аккаунте | `getCurrentAccount` или `getAccountsById` для определения аккаунта и валюты; затем `createAd` для каждого элемента |
| `upload_media` | Загрузить файл и получить ID для последующих объявлений | `uploadAdPhoto`, `uploadAdVideo` или `uploadWebsitePhoto` |

Один инструмент `create_ads` обслуживает и одиночный, и пакетный сценарий:
для одного объявления передаётся список из одного элемента.
Общие параметры аккаунта задаются один раз. Повторяющиеся объявления,
ключи и ID не удаляются и не переставляются сервером.

Отдельная загрузка медиа позволяет повторно использовать один ID в нескольких
объявлениях того же аккаунта. В `create_ads` передаются готовые ID,
поэтому повтор создания с тем же ключом не приводит к новой загрузке файла
и изменению параметров запроса.

## create_ads

Сигнатура:

```python
async def create_ads(
    ads: list[NewAd],
    account_id: str | None = None,
    dry_run: bool = False,
    stop_on_error: bool = True,
) -> dict:
    ...
```

`ads` должен содержать хотя бы один элемент. `account_id` использует уже
принятые в проекте правила: явное значение, настройка окружения, владелец токена.
Во время выполнения аккаунт определяется один раз и применяется ко всему пакету.
В ответе указывается конкретный ID аккаунта и его валюта.

### NewAd

Сохраняем имена параметров API, чтобы не вводить дополнительный словарь терминов.
Используем Pydantic-модель с описаниями полей и запретом неизвестных полей.

| Поле | Требование или значение по умолчанию |
|---|---|
| `title` | Обязательно, внутреннее название: 1–128 байт UTF-8 |
| `promote_url` | Обязательно, ссылка назначения: 1–256 символов |
| `cpm` | Обязательно, положительное конечное число в валюте аккаунта |
| `placement` | Обязательно: `channel_post`, `bot_banner`, `search_result`, `video_banner` |
| `target` | Обязательно, одна из четырёх типизированных моделей таргетинга |
| `idempotency_key` | Обязательно, непустая строка до 128 символов для одного объявления |
| `text` | 1–160 символов; обязателен для всех типов таргетинга, кроме `search` |
| `initial_budget` | По умолчанию `0`; перевод из бюджета аккаунта в бюджет объявления |
| `is_paused` | По умолчанию `true`, с учётом поведения дат запуска и остановки, описанного ниже |
| `daily_budget_limit` | По умолчанию не передаётся; API использует `0`, то есть отсутствие дневного лимита |
| `photo_id`, `video_id` | Необязательны; одновременно допускается только одно медиа |
| `show_userpic` | Необязателен, аватар рекламируемого канала или бота |
| `impression_frequency` | Необязателен, 1–4 показа пользователю в сутки |
| `website_name`, `website_photo_id`, `button` | Параметры внешнего сайта; название обязательно для внешней ссылки |
| `conversion_event_id` | Необязательный ID уже существующего события конверсии |
| `additional_info` | Необязательная дополнительная информация, до 64 символов |
| `activate_date`, `deactivate_date` | Необязательные Unix timestamps; правила и округление задаёт API |
| `schedule` | Необязательная типизированная модель расписания в формате API |

`return_target` не нужен как обязательный шаг: по умолчанию возвращаем компактный
результат. Подробности созданного объявления доступны через `get_ads_by_id`.

В первой реализации `schedule` сохраняет поля API: `week_hours_mask` из семи
чисел, `timezone` как смещение UTC в секундах и `use_viewer_timezone`.
Преобразование удобных пользовательских расписаний в маски можно добавить
отдельно, без изменения основного сценария создания.

### Таргетинг

`target` — discriminated union по полю `type`:

| `type` | Основные параметры |
|---|---|
| `channels` | `channel_ids` либо `language_codes` либо `topic_ids` с одним языком; исключения каналов и тем |
| `users` | Страны, локации, языки, темы, аудитории каналов, ретаргетинг, устройства и поддерживаемые исключения |
| `bots` | `bot_ids` |
| `search` | `search_queries` |

`placement` и `target.type` — разные параметры. Их совместимость проверяется
отдельно; место размещения не угадывается по таргетингу.

Каналы и боты принимаются как `@username` или ранее разрешённые этим аккаунтом
числовые ID. Для usernames не нужен отдельный обязательный вызов
`getTargetChannel` или `getTargetBot` перед каждым `createAd`.

Для моделей проверяем документированные ограничения и сочетания полей:
например, в `channels` нельзя одновременно задавать конкретные площадки
и языки/темы; локации `users` требуют одну страну; медиа разрешено только
для поддерживающих его типов таргетинга. Неизвестные поля не игнорируются.
Контентную модерацию и доступность назначения определяет Telegram.

### Бюджет, модерация и показы

Вызов с настройками по умолчанию создаёт объявление с нулевым бюджетом на паузе.
Это обычное объявление Telegram Ads, без собственного серверного хранилища черновиков.

Важно различать три эффекта:

- `initial_budget > 0` переводит деньги из аккаунта в объявление.
- При создании с ненулевым бюджетом Telegram может автоматически отправить
  объявление на модерацию. `is_paused=true` не является запретом модерации.
- `is_paused` управляет показами; API игнорирует этот параметр, если переданы
  `activate_date` или `deactivate_date`. Поэтому наличие паузы по умолчанию
  не гарантирует паузу при явно заданных датах.

Размеры CPM и бюджета трактуются только в валюте выбранного аккаунта.
Сервер не подбирает ставку, не подставляет универсальный минимум и не обрезает
значения самостоятельно: API может округлить их по правилам валюты.
Возвращаем фактические значения из ответа Telegram.

### Проверка и выполнение

Pydantic проверяет весь пакет до первой записи. Затем `create_ads` выполняет
его через одну операцию `TeleAdRunner` и один `Client`, последовательно
вызывая `create_ad` для элементов в исходном порядке.

`dry_run=true` выполняет только локальную проверку и возвращает параметры
после применения значений по умолчанию. API не вызывается: такая проверка
не подтверждает доступность аккаунта, остаток бюджета, допустимость ставки,
валидность media ID или прохождение модерации.

При `stop_on_error=true` первая ошибка останавливает дальнейшее создание.
Оставшиеся элементы отмечаются как `not_attempted`.
При `stop_on_error=false` независимые ошибки отдельных объявлений сохраняются,
а обработка продолжается. Ошибки авторизации, прав доступа и ограничения
частоты запросов в любом случае останавливают пакет.
Неожиданные ошибки клиента также прекращают дальнейшие записи.

У API нет транзакции для такого пакета: уже созданные объявления сохраняются.
Автоматического удаления или обратного перевода бюджета при частичном результате нет.

### Повторы и ответ

Для каждого объявления вызывающий клиент передаёт свой `idempotency_key`.
Для повтора одной операции он сохраняет тот же ключ и те же параметры.
Telegram хранит результаты по ключам до 24 часов; поздний повтор может
создать новое объявление. Автоматический ключ TeleAd защищает только повторы
внутри отдельного вызова клиента и не заменяет ключ в контракте MCP.

Проверку уникальности ключей и дедупликацию объявлений сервер не добавляет.
Совпадение ключа с другими параметрами проверяет Telegram API.

Ответ содержит:

- `account_id`, `currency`;
- счётчики по исходам и `complete`, равный `true`, только если успешны все элементы;
- `results` в исходном порядке: `index`, `idempotency_key`, `outcome`;
- при успехе — `ad_id`, `title`, `status`, `is_paused`, `cpm`, `remaining_budget`;
- при ошибке — безопасное сообщение и код API, если он доступен.

`outcome` принимает значения `succeeded`, `failed`, `unknown`, `not_attempted`.
Сетевая ошибка после исчерпания повторов даёт `unknown`: отсутствие ответа
не доказывает, что объявление не создано. Повторять нужно с прежним ключом.

Успешный ответ не называем «новое объявление создано», если это мог быть
повтор запроса: TeleAd не отдаёт признак `Idempotent-Replayed` в модели `Ad`.

Пример вызова для одного текстового объявления:

```json
{
  "ads": [
    {
      "idempotency_key": "3b284a89-7d93-48e0-986d-7866a90d8801",
      "title": "Канал: первый вариант",
      "text": "Маршруты, снаряжение и заметки о путешествиях — в нашем канале.",
      "promote_url": "https://t.me/example_channel",
      "cpm": 0.3,
      "placement": "channel_post",
      "target": {
        "type": "channels",
        "channel_ids": ["@example_placement"]
      },
      "initial_budget": 0,
      "is_paused": true
    }
  ]
}
```

Значение CPM в примере условное; его допустимость зависит от аккаунта
и параметров объявления. Для нескольких вариантов добавляются элементы `ads`.

## upload_media

Сигнатура:

```python
async def upload_media(
    file_path: str,
    kind: Literal["ad_photo", "ad_video", "website_photo"],
    account_id: str | None = None,
) -> dict:
    ...
```

`file_path` — абсолютный путь к обычному файлу на машине, где запущен сервер.
Инструмент читает этот файл и отправляет в Telegram Ads. Base64 в аргументах
MCP и скачивание по произвольному URL не требуются.

`kind` выбирает один из трёх конкретных методов загрузки. Ответ содержит
конкретный `account_id`, `kind` и поля соответствующего ответа API:
`photo_id`/`photo_url` либо `video_id`/`video_url`.
Этот ID передаётся в `create_ads` и может использоваться повторно только
в том же рекламном аккаунте.

Проверяем путь, доступность файла и ограничения выбранного вида загрузки.
Проверки размеров изображения и длительности видео требуют чтения метаданных;
одной проверки расширения файла недостаточно. Результат загрузки не считается
гарантией прохождения модерации.

## Дополнительные методы

Справочники языков, тем и стран уже доступны через `get_targeting_options`,
поиск локаций — через `get_target_locations`, а получение каналов
и ботов — через `get_target_channel` и `get_target_bot`. Остальные операции
из таблицы остаются направлениями дальнейшего расширения:

| Сценарий | Методы Telegram Ads API |
|---|---|
| Получение справочников таргетинга | `getTargetLanguagesList`, `getTargetTopicsList`, `getTargetCountriesList`, `getTargetLocationsList` |
| Разрешение username и получение сведений о площадке | `getTargetChannel`, `getTargetBot` |
| Пополнение созданного объявления | `increaseAdBudget` |
| Редактирование и снятие паузы | `editAd` |
| Явная отправка на модерацию | `submitAdForReview`, только для статуса `ready_for_review` |

В `create_ads` нет обязательного вызова `submitAdForReview` после создания:
он применим не ко всем состояниям и может быть избыточен после автоматической отправки.
Создание пикселя, событий, ретаргетинговых аудиторий и финансовые операции
после создания остаются самостоятельными задачами.

## Размещение в проекте и проверки

- `models/ad_creation.py`: `NewAd`, варианты таргетинга, расписание и модели результата.
- `operations/ad_creation.py`: выполнение пакета и результаты отдельных элементов.
- `tools/ads.py`: `create_ads` и формирование ответа MCP.
- `tools/media.py`: `upload_media`.

При регистрации обновлены общий `instructions` сервера, описание проекта
и список инструментов в README. Операции чтения и записи имеют разные annotations.

Для обоих инструментов `read_only_hint=false`, `open_world_hint=true`.
Для `create_ads` консервативно ставим `destructive_hint=true`, поскольку он
может перераспределить бюджет и запустить показы при соответствующих параметрах.
Для добавления медиа `destructive_hint=false`.
`idempotent_hint=false`: загрузки не имеют документированной защиты от повторов,
а идемпотентность создания ограничена временем хранения ключа Telegram.
Фактические эффекты каждого режима описываются в многострочном докстринге.

Офлайн-проверки покрывают:
передача всех полей, выбор аккаунта, ключи повторов, одиночный и пакетный вызов,
ошибка в середине пакета, неизвестный исход сетевого запроса, частичный ответ,
локальный dry run без API, отсутствие тихого удаления повторов, загрузка
и переиспользование медиа, ограничения совместимости и регистрация MCP-схем.
