# Разработка ads-telegram-mcp

Пользовательская инструкция находится в [README](../README.md).
Здесь описаны устройство сервера, добавление инструментов и локальные проверки.

Сервер использует официальный MCP Python SDK 2.x (`MCPServer`).
Инструменты обращаются к Telegram Ads через синхронный клиент TeleAd.

## Сборка сервера и настройки

`create_server(settings: Settings)` принимает готовые настройки.
В точке запуска вызывается `create_server(settings=Settings())`.
`register_tools` передаёт сервер и `TeleAdRunner` модулям областей.
Каждый модуль регистрирует функции декоратором `@server.tool(...)`.
Регистрация инструментов не выполняет запросов к API.

stdout занят протоколом MCP, сообщения SDK идут в stderr.
Альтернативная точка запуска — `uv run --locked python main.py`.

`Settings` использует `pydantic-settings`. Путь к `.env` вычисляется
относительно модуля `config.py`, поэтому не зависит от текущего рабочего каталога.
Файл читается в UTF-8; посторонние ключи игнорируются.

Приоритет источников:

1. Явные аргументы `Settings(...)`.
2. Переменные окружения с префиксом `TELEGRAM_ADS_`.
3. `.env` в корне проекта.
4. Значения полей по умолчанию.

Пустая переменная окружения тоже перекрывает `.env`. Пробелы по краям значений
удаляются; пустой `account_id` становится `None`. Модель настроек неизменяема,
поле токена исключено из repr и сериализации.
Для изоляции проверок от локального `.env` передавайте `Settings(_env_file=None, ...)`.

Без токена сервер запускается и отдаёт `tools/list`; вызов API-инструмента
возвращает MCP tool error с именем недостающей переменной.
Браузерная сессия Telegram Ads не авторизует API-клиент.

## Структура проекта и добавление инструментов

```text
ads_telegram_mcp/
  __main__.py        # python -m
  server.py          # сборка MCPServer и запуск stdio
  config.py          # pydantic-settings: окружение и .env проекта
  execution.py       # типизированные операции с TeleAd, рабочий поток, ошибки MCP
  operations/
    ads_stats.py     # сбор и агрегирование статистики нескольких объявлений
  tools/
    __init__.py      # явный реестр областей
    common.py        # общие типы параметров и annotations
    accounts.py      # аккаунты
    ads.py          # объявления
    stats.py        # статистика и отчёты
docs/
  development.md     # инструкция для разработчика
  telead-coverage.md # краткая сверка покрытия API
tests/
  test_server.py    # проверки без сети
  test_execution.py # составные операции и время жизни Client
  test_settings.py  # источники настроек и их приоритет
  test_ads_stats.py # пагинация, агрегирование и частичные ошибки get_ads_stats
```

Для новой области добавьте `tools/targeting.py`, `budgets.py`, `audiences.py`,
`media.py` или `pixel.py` с `register(server, runner)` и включите модуль
в реестр. Внутри регистрируйте функции с явными Python-параметрами через
`@server.tool(...)`; вызывайте методы клиента через `await runner.run(operation)`.
`TeleAdRunner.run` принимает синхронную функцию `Client -> T` и возвращает `T`
без преобразования моделей в словари. Для короткого вызова подойдёт lambda,
для нескольких API-вызовов и обработки результатов — обычная функция.

```python
from mcp.server import MCPServer
from telead import Client
from telead.models import Ad

from ..execution import TeleAdRunner
from .common import READ_ONLY


def register(server: MCPServer, runner: TeleAdRunner) -> None:
    @server.tool(annotations=READ_ONLY)
    async def list_active_ads() -> dict:
        """Get active ads from the token owner's account.

        Only the first 20 ads are inspected.
        """
        def load(client: Client) -> list[Ad]:
            account = client.get_current_account()
            page = client.get_ads_list(account_id=account.account_id, limit=20)
            return [ad for ad in page.ads if ad.status == "active"]

        ads = await runner.run(load)
        return {"ads": [ad.raw for ad in ads]}
```

Пример явно выбирает владельца токена и обрабатывает одну страницу объявлений.
Он иллюстрирует расширение сервера и не входит в текущий набор инструментов.

`TeleAdRunner` создаёт один Client на всю операцию и закрывает его по её
завершении, включая ошибку. Операция целиком выполняется в рабочем потоке:
цикл MCP не блокируется, HTTP-сессии не разделяются между параллельными операциями.
Генераторы и итераторы TeleAd нужно прочитать внутри операции, пока Client открыт.
Составные операции вызывают методы Client и обычные функции обработки;
вызывать собственные MCP-инструменты через MCP внутри сервера не требуется.
MCP-инструмент формирует конечный ответ: использует `model.raw` для исходного
payload либо выбирает и агрегирует поля типизированных моделей. Сериализацию
ответа в JSON выполняет MCP SDK. Общего рекурсивного адаптера нет.
Реальные методы TeleAd доступны только из кода; универсального MCP-инструмента
для произвольного API-вызова нет.

Для будущих изменений объявлений задавайте собственные MCP annotations:
`READ_ONLY` предназначен только для чтения. При добавлении бюджетов/создания
объявлений явно опишите последствия и передавайте стабильные idempotency keys
для повторения одной бизнес-операции; автоключ TeleAd защищает только повторы
внутри одного вызова клиента. Сокращение ответов и выбор областей при запуске
можно добавлять на этих границах отдельно.

`READ_ONLY` содержит декларации поведения для MCP-клиента, а не ограничения
исполняемого кода.

## Ответы и ошибки

Базовые инструменты возвращают исходные ответы API из `model.raw`.
Массивы оборачиваются в `accounts`, `ads`, `stats` или `report`.
Новые поля API сохраняются. `get_ads_stats` возвращает агрегаты и, по запросу,
исходные строки статистики; его контракт описан ниже.

Ошибки TeleAd преобразуются в MCP tool errors. Наружу не передаются
тела ошибочных ответов и транспортные сообщения. Для API-ошибок сохраняются
код и HTTP-статус. Timeout чтения 30 секунд, максимум один повтор средствами
TeleAd; с учётом подключения и ожидания перед повтором весь вызов может длиться дольше.

Ограничение групповых запросов до 100 ID задано в схемах инструментов;
оно не означает, что такой же предел установлен Telegram API.
Явный `ToolError` из составной операции передаётся без замены.

## Составная статистика get_ads_stats

Операция `operations/ads_stats.py` получает готовый `Client` и возвращает
типизированный `AdsStatsBatch`. При непустом `ad_ids` она напрямую запрашивает
статистику выбранных ID, без предварительного получения списка объявлений.
Для пустого списка, `None` или пропущенного параметра получает все страницы
`get_ads_list` по 100 записей и собирает уникальные ID без фильтра по статусам.
Повтор курсора или пустая страница с непустым курсором прерывают операцию
ошибкой, чтобы неполный список не был принят за полный.

Для каждого ID последовательно вызывается `get_ad_stats`; все вызовы используют
один `Client` в одном рабочем потоке. Операция суммирует показатели
типизированных `AdStatItem`. Расход складывается через `Decimal`; преобразование
в JSON-число выполняется при формировании ответа инструментом.
Показатели разных валют внутри одного ряда не складываются.

При `include_timeseries=false` строки интервалов не сохраняются в результате
операции. `include_timeseries=true` сохраняет их для выдачи через `point.raw`.
Пустой ряд даёт `data_points=0` и `totals=null`, без предположений о валюте.
Непустой ряд с нулевыми показателями возвращает нулевые суммы.

Ошибки API отдельных объявлений и транспортные ошибки после повторов TeleAd
сохраняются в `AdStatsFailure`; следующие ID продолжают обрабатываться.
Ошибки авторизации, прав доступа и ограничения частоты запросов прекращают
всю операцию. Общая функция `public_error_message` в `execution.py` формирует
сообщения как для ошибок всего инструмента, так и для отдельных объявлений,
без тел ответов, транспортных подробностей и токена.

Инструмент возвращает округлённые `from_time` и `to_time`, `interval`,
`total_count`, `succeeded_count`, `failed_count`, `complete`, `ads` и `errors`.
Границы округляются до API-вызовов; пустой период после округления отклоняется.
`complete` равен `false`, если запрос статистики хотя бы одного ID завершился ошибкой.
Успешные элементы `ads` содержат `ad_id`, `data_points`, `totals` и необязательный
`stats`. В `errors` находятся `ad_id` и безопасное сообщение `error`.

## Соответствие инструментов методам клиента

| Область | MCP-инструмент | TeleAd |
|---|---|---|
| Аккаунты | `get_current_account` | `get_current_account` |
| Аккаунты | `list_related_accounts` | `get_related_accounts_list` |
| Аккаунты | `get_accounts_by_id` | `get_accounts_by_id` |
| Объявления | `list_ads` | `get_ads_list` |
| Объявления | `get_ads_by_id` | `get_ads_by_id` |
| Статистика | `get_account_stats` | `get_account_stats` |
| Статистика | `get_ad_stats` | `get_ad_stats` |
| Статистика | `get_ads_stats` | `get_ads_list` + `get_ad_stats`; с выбранными ID — только `get_ad_stats` |
| Отчёты | `get_account_report` | `get_account_report` |

Сверка полного интерфейса библиотеки с документацией API:
[telead-coverage.md](telead-coverage.md). Покрытие библиотеки шире текущего
набора MCP-инструментов.

## Локальные проверки

Из корня проекта:

```sh
uv run --locked python -m unittest discover -s tests -v
```

HTTP в проверках подменён; subprocess stdio запускается без токена.
Проверяются пагинация, выбор аккаунта, сохранение новых полей API,
валидация, скрытие транспортных подробностей, MCP initialize/list/call и завершение,
составные операции с типизированными результатами, рабочий поток и закрытие Client.
Никаких запросов к реальным кабинетам.
